# 開発・テスト

## 補助コマンド

通常問題の候補計画は次のコマンドで確認できます。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD
```

暗記語句問題はモードと問題数を指定します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD --mode term-recall --count 10
```

採点済みSessionは `record` でprogressへ反映します。理解・応用問題では `--mode standard`、暗記語句問題では `--mode term-recall` を使います。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py record \
  --root . --date YYYY-MM-DD --session N --mode standard
```

詳しい前提条件と失敗時の扱いは [セッション形式](../参照資料/session-format.md)を参照してください。

全回答済みSessionを古い順に採点した結果、すでに後の日付の進捗が記録済みで`record`が時系列保護により停止したときは、次でprogressを再構築します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py rebuild --root .
```

回答欄が空の問題だけを確認・更新するには、次を実行します。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py unanswered --root .
```

## ローカルテスト

補助ロジックとSkill構造の回帰テストは標準ライブラリだけで実行できます。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -v
```

テストファイル名の必須接頭辞 `test_` より後ろ、テストクラス名、`test_` で始まるテストメソッド名は、ローカルおよびCIのログから確認内容が分かるよう日本語で記述します。新しいテストでもこの命名規則を維持します。

## 継続的インテグレーション

GitHub Actionsは、ブランチ名にかかわらずすべての `push` で同じテストをPython 3.14上で実行します。設定は `.github/workflows/python-tests.yml` にあります。

## 文書変更時の確認

READMEから詳細を移動するときは、情報を削除せず適切な `docs/` 文書へ移し、ルートREADMEから到達できるようにします。実装上の厳密な制約は `参照資料/` を正本とし、概要文書と矛盾させません。相対リンクは移動先を基準に更新し、テストで主要文書の存在とREADMEからの参照を確認します。
