## 問題難易度

| Level | 主な要求 |
|---:|---|
| 1 | 用語を正しく定義する |
| 2 | 基本原理と目的を説明する |
| 3 | 成立条件、対策、類似概念を比較する |
| 4 | 短いシナリオへ適用して判断理由を述べる |
| 5 | 科目B相当の文章・設定・ログを関連付けて解く |
| 6 | 複数の妥当な選択肢、制約、残存リスクまで論じる |

理解度の目安は、0〜39ならLevel 1、40〜59ならLevel 2、60〜74ならLevel 3、75〜87ならLevel 4、88〜94ならLevel 5、95〜100ならLevel 6。誤答直後は一段下げてもよい。高得点が続く分野では一段上げる。

## 問題別の採点

問題が要求する観点だけを選び、選んだ配点を100点へ正規化する。既定配点は次のとおり。

| 観点 | 基本配点 | 評価する内容 |
|---|---:|---|
| 定義 | 15 | 何であるか、何でないか |
| 原理・目的 | 20 | なぜ成立・機能するか |
| 成立条件 | 15 | 必要条件、前提、境界条件 |
| シナリオ適用 | 20 | ログ・通信・設定からの推論、影響 |
| 対策と理由 | 20 | 対策が効く箇所、運用、迂回や限界 |
| 比較・限界 | 10 | 類似概念との差、残存リスク |

採点は意味内容で行う。同義表現を認め、問題が求めていない専門語の欠如だけで減点しない。重大な因果逆転、攻撃者と被害者の混同、安全でない対策の推奨は大きく減点する。回答が空なら採点せず、セッションを未採点のままにする。

各問題には以下を短く追記する。

- `Score: n / 100`
- 良かった点
- 足りない点・誤解
- 模範的な説明（原則150〜350字程度。必要なら箇条書き）
- 次回確認する観点

## 語句理解度の更新

問題点を `q`、Levelを `L` とする。低難易度の満点だけで応用理解を100にしないため、証拠スコア `e` を計算する。

```text
level_cap = {1: 70, 2: 80, 3: 88, 4: 94, 5: 100, 6: 100}
e = min(q, level_cap[L])
```

初回は `new_score = e`。2回目以降は、直近の証拠を反映しつつ過去の定着も残す。

```text
alpha = 0.45              # Attempts 1〜2
alpha = 0.35              # Attempts 3〜5
alpha = 0.30              # Attempts 6以上
q < 40 なら alpha += 0.10 # 強い誤解を早く反映
new_score = round(old_score * (1 - alpha) + e * alpha)
```

複数概念を1問で扱った場合、`Primary Terms` の中心概念だけを上式で数値更新する。独立した評価対象なら最初からPrimary Termsへ含める。`Related Terms` はNotesと次回候補には使うが、Score・Average・Attemptsは更新しない。これにより、補助的に触れただけの概念を定着済みと誤認しない。Notesには点数そのものではなく「説明できた点 / 次に確認する一点」を残す。

`Last Score` には直近問題の得点、`Last Session` には最新の `YYYY-MM-DD#Session番号`、`Applied Sessions` には反映済みSessionキーを保存する。Applied Sessionsに含まれるSessionを再処理するときはScore・Average・Attemptsを再更新しない。より新しいSessionを反映済みの概念へ古いSessionを後から適用しようとした場合は停止し、時系列順での処理を求める。直近得点が不明な旧データには同日再出題ペナルティを掛けない。

## 分野理解度の更新

分野スコアは、所属語句の現在スコア70%、その分野の直近5問の得点30%を目安にする。証拠が2問未満なら `Provisional` と注記する。未評価概念を0点にしない。

| Score | Level |
|---:|---|
| 0〜39 | Beginner |
| 40〜69 | Intermediate |
| 70〜84 | Proficient |
| 85〜100 | Advanced |

`Due Terms` は `Next Review <= 今日` の語句数。Notesには強みと次の弱点を一つずつ記録する。

## 復習間隔と忘却度

現在理解度から基本間隔を決める。

| Score | 基本間隔 |
|---:|---:|
| 0〜39 | 1日 |
| 40〜59 | 2日 |
| 60〜74 | 5日 |
| 75〜89 | 12日 |
| 90〜100 | 30日 |

直近得点が60未満なら半分（最低1日）、90以上かつLevel 4以上なら1.25倍、Level 5以上で高得点が2回以上続くなら1.5倍まで延ばす。`Next Review = Last Studied + 補正後日数`。

選択時の忘却度は次を目安に0〜40へ丸める。

```text
elapsed = 今日 - Last Studied
forgetting = min(40, 35 * elapsed / 基本間隔)
```

期限を過ぎたら高くなり、期限前でも徐々に上がる。現在スコア自体を毎日書き換えず、忘却度を選択優先度へ反映する。

## 出題優先度と配分

```text
priority = weakness + forgetting + subject_b + unseen + relation + balance - recent_penalty

weakness      = 0.45 * (100 - Score)                 # 未学習は別扱い
forgetting    = 0〜40
subject_b     = 科目B中心15、A/B 10、科目A 3
unseen        = 未学習20
relation      = 弱い概念と強く関連するなら0〜10
balance       = 最近少ない分野へ0〜10
recent_penalty= 当日学習済みかつLast Scoreが60点以上なら30
```

通常5問なら「弱点2、復習期1、新規1、発展1」を基準にする。問題数に応じて40% / 25% / 20% / 15%へ丸め、候補不足時は優先度順に補う。同一分野の選択が増えるごとに小さな重複ペナルティを付ける。明示された「Webだけ」「新規多め」などの希望はこの配分より優先する。

科目B関連は70〜85%を目安にするが、初回診断の分野網羅や明示された分野指定を優先してよい。単純なランダム抽出は禁止し、同点の入れ替えにだけ日付ベースの決定的なタイブレークを使う。
