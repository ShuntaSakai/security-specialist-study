# 情報処理安全確保支援士・適応学習ノート

情報処理安全確保支援士試験（セキスペ）の科目A・科目Bを、Markdownで記録しながら反復学習するためのリポジトリです。主眼は用語暗記ではなく、**定義・原理・成立条件・シナリオ・対策・類似概念との差を自分の言葉で説明できること**にあります。

## ディレクトリ構成

```text
security-specialist-study/
├── AGENTS.md                         # リポジトリ内の自然言語リクエストをSkillへ誘導
├── README.md
├── sessions/                         # 日ごとの問題、回答、採点結果
├── progress/
│   ├── terms.md                      # 語句・概念ごとの理解度
│   ├── domains.md                    # 分野ごとの理解度
│   └── history.md                    # セッション単位の履歴
├── references/
│   ├── taxonomy.md                   # 分野分類、出題候補、関連概念
│   ├── scoring-rules.md               # 採点・理解度・復習間隔の規則
│   └── session-format.md              # セッションMarkdownの形式
└── skills/security-specialist-trainer/
    ├── SKILL.md                       # Codex Skill本体
    ├── agents/openai.yaml             # SkillのUIメタデータ
    ├── scripts/study_helper.py         # 適応出題候補の決定支援
    └── tests/                          # 選択式・構造の回帰テスト
```

学習の正本は `sessions/` と `progress/` のMarkdownです。補助スクリプトは候補の順位付けにだけ使い、学習履歴をJSONへ隠しません。

## 各Markdownの役割

- `sessions/YYYY-MM-DD.md`: 問題、ユーザーの回答、問題別採点、短い模範説明を保存します。同じ日に複数回学習すると `Session 2`、`Session 3` と追記します。
- `progress/terms.md`: 概念単位の現在スコア、平均点、出題回数、最終学習日、次回復習日、関連概念、弱点メモを保存します。
- `progress/domains.md`: 分野単位の理解度を、語句スコアだけでなく直近の解答実績も含めて推定します。
- `progress/history.md`: 各セッションの平均点、科目B比率、弱点、次の復習候補を時系列で保存します。
- `references/taxonomy.md`: 出題分野、代表概念、科目B重要度、前提・関連関係を定義します。
- `references/scoring-rules.md`: 100点評価、理解度更新、難易度、忘却度、復習間隔の共通規則です。

## Skillの起動条件

`security-specialist-trainer` は、次のような意図で使用します。

- 「問題作って」「今日の問題」「セキスペ勉強しよう」「5問出して」
- 「軽く復習」「Web系多め」「科目Bっぽく」「苦手中心」「新しい単語多め」
- 「採点して」「答え合わせして」「レビューして」
- 「今日の結果どう？」「理解度見せて」「今の弱点は？」

このリポジトリを作業場所として開けば、`AGENTS.md` が上記の自然言語リクエストをローカルSkillへ誘導します。Skillを明示する場合は `$security-specialist-trainer` と指定します。

## 出題アルゴリズム

初回は診断フェーズとして、既定で8問をWeb、ネットワーク、暗号、認証、PKI、DNS、メール、マルウェアから1問ずつ出します。難易度はLevel 2〜3を中心にし、最初から得意・不得意を決めつけません。通常セッションは5問です。

通常時は、おおむね次の配分で候補を選びます。

| 枠 | 目安 | 目的 |
|---|---:|---|
| 弱点 | 40% | 低理解度の基礎を説明し直す |
| 復習期 | 25% | 忘れ始める時期の想起練習 |
| 新規 | 20% | 前提関係と頻出度に沿って範囲を広げる |
| 発展 | 15% | 得意分野を比較・ログ・シナリオ問題へ進める |

各候補の優先度には、弱点度、復習期限からの経過、科目B重要度、未学習ボーナス、最近の分野偏り、弱い概念との関連性を使います。同日に正解した概念には再出題抑制を掛けます。科目B関連を原則70〜85%にしつつ、指定された問題数や分野を優先します。

問題選択の補助結果は次のコマンドでも確認できます。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date 2026-08-09
```

## 採点と理解度更新

採点はキーワード数ではなく、問題に必要な次の観点を選び、該当観点の配点を100点へ正規化します。

1. 定義
2. 原理
3. 成立条件
4. 攻撃・利用シナリオ
5. 対策とその理由
6. 類似概念との差・限界

問題別に点数、良かった点、足りない点、短い模範説明をセッションへ追記します。その後、`terms.md`、`domains.md`、`history.md` を同じ採点内容から更新します。低難易度での満点だけで応用力100とは見なさず、Level 1〜4の証拠スコアには上限を設けます。詳しい式は [references/scoring-rules.md](references/scoring-rules.md) にあります。

## 復習タイミング

基本間隔は現在理解度に応じて1日、2日、5日、12日、30日です。直近の点数、出題難易度、連続した理解の安定性で補正します。期限前は出しすぎず、期限が近い・過ぎた概念は忘却度を上げます。100点の概念も除外せず、Level 5相当で安定していれば数週間後に再びシナリオ問題として扱います。

## 実際の利用例

1. チャットで「問題作って」と依頼する。
2. Codexが `sessions/YYYY-MM-DD.md` に問題を作る。
3. 各 `### 回答` の下へMarkdownで回答を書く。
4. チャットで「採点して」と依頼する。
5. 採点結果と3つのprogressファイルが更新される。
6. 翌日以降、再び「問題作って」と依頼する。

分量や傾向は自然文で変更できます。例: 「今日は3問」「Web系を多めに」「新しい概念多め」「科目Bのログ分析っぽく」。

## 検証

補助ロジックとSkill構造の回帰テストは標準ライブラリだけで実行できます。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -v
```
