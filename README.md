# 情報処理安全確保支援士・適応学習ノート

情報処理安全確保支援士試験（セキスペ）の科目A・科目Bを、Markdownで記録しながら反復学習するためのリポジトリです。短い暗記語句問題で定義を想起する力と、通常説明問題で**原理・成立条件・シナリオ・対策・類似概念との差を自分の言葉で説明する力**を相互に補強します。

## ディレクトリ構成

```text
security-specialist-study/
├── .github/workflows/python-tests.yml # 全ブランチのpushでPythonテストを実行
├── AGENTS.md                         # リポジトリ内の自然言語リクエストをSkillへ誘導
├── README.md
├── sessions/                         # 日ごとの問題、回答、採点結果
│   ├── 理解・応用問題/                 # 原理・条件・対策・応用を問う問題
│   └── 暗記語句問題/                 # 語句の意味を短く説明する問題
├── progress/
│   ├── terms.md                      # 語句・概念ごとの理解度
│   ├── domains.md                    # 分野ごとの理解度
│   └── history.md                    # セッション単位の履歴
├── references/
│   ├── taxonomy.md                   # 分野分類、出題候補、関連概念
│   ├── scoring-rules.md               # 採点・理解度・復習間隔の規則
│   └── session-format.md              # セッションMarkdownの形式
├── 復習用/                            # 図解を含む、繰り返し使う復習ノート
└── skills/security-specialist-trainer/
    ├── SKILL.md                       # Codex Skill本体
    ├── agents/openai.yaml             # SkillのUIメタデータ
    ├── scripts/study_helper.py         # 出題候補選択と採点結果の冪等反映
    └── tests/                          # 選択式・構造の回帰テスト
```

学習の正本は `sessions/` と `progress/` のMarkdownです。補助スクリプトは候補の順位付けと、採点済みSessionからprogressへの冪等な反映を行います。学習履歴をJSONへ隠しません。

## 各Markdownの役割

- `sessions/理解・応用問題/YYYY-MM-DD.md`: 理解・応用問題、ユーザーの回答、問題別採点、短い模範説明を保存します。
- `sessions/暗記語句問題/YYYY-MM-DD.md`: 暗記語句問題とその回答・採点を保存します。同じ日のSession番号は両ディレクトリを通した連番にします。
- `progress/terms.md`: 概念単位の総合理解度、暗記語句／通常説明別の理解度、平均点、直近点、科目区分、出題回数、反映済みSession台帳、最終学習日、次回復習日、関連概念、弱点メモを保存します。
- `progress/domains.md`: 分野単位の理解度を、語句スコアだけでなく直近の解答実績も含めて推定します。
- `progress/history.md`: 各セッションの平均点、科目B比率、弱点、次の復習候補を時系列で保存します。
- `復習用/*.md`: 複数の主体・処理順・分岐を図で確認した方がよいテーマを、Mermaid図として保存します。主体が関わる流れでは、誰が誰へ何をするかを明示します。既存の図と同じ学習目的の図は重複作成しません。
- `references/taxonomy.md`: 出題分野、代表概念、科目B重要度、前提・関連関係を定義します。
- `references/scoring-rules.md`: 100点評価、理解度更新、難易度、忘却度、復習間隔の共通規則です。

## Skillの起動条件

`security-specialist-trainer` は、次のような意図で使用します。

- 「問題作って」「今日の問題」「セキスペ勉強しよう」「5問出して」
- 「暗記単語問題作って」「暗記語句問題作って」「単語問題10問」「暗記問題20問作って」
- 「軽く復習」「Web系多め」「科目Bっぽく」「苦手中心」「新しい単語多め」
- 「採点して」「答え合わせして」「レビューして」
- 「今日の結果どう？」「理解度見せて」「今の弱点は？」

このリポジトリを作業場所として開けば、`AGENTS.md` が上記の自然言語リクエストをローカルSkillへ誘導します。Skillを明示する場合は `$security-specialist-trainer` と指定します。

作業中に得られた、再利用可能な正確性・安全性・分かりやすさに関する知見は、必要に応じてSkill、手順書、参照資料へ反映します。一時的な事情や個別案件だけに固有の内容は恒久ルールにしません。

変更によって不要になった可能性のあるファイル、生成物、重複ノートは自動削除しません。削除候補と理由・影響を示したうえで、利用者に削除の判断を依頼します。

## 出題アルゴリズム

初回は診断フェーズとして、既定で8問をWeb、ネットワーク、暗号、認証、PKI、DNS、メール、マルウェアから1問ずつ出します。難易度はLevel 2〜3を中心にし、最初から得意・不得意を決めつけません。通常セッションは5問です。

通常時は、おおむね次の配分で候補を選びます。

| 枠 | 目安 | 目的 |
|---|---:|---|
| 弱点 | 40% | 低理解度の基礎を説明し直す |
| 復習期 | 25% | 忘れ始める時期の想起練習 |
| 新規 | 20% | 前提関係と頻出度に沿って範囲を広げる |
| 発展 | 15% | 得意分野を比較・ログ・シナリオ問題へ進める |

各候補の優先度には、弱点度、復習期限からの経過、科目B重要度、未学習ボーナス、最近の分野偏り、弱い概念との関連性を使います。同日に正解した概念には再出題抑制を掛けます。科目B関連を原則70〜85%にしつつ、指定された問題数や分野を優先します。指定できる問題数は通常問題・暗記語句問題とも1〜30問です。

### 暗記語句問題

暗記語句モードは、語句を見て「何であるか・何のためか・重要な特徴」を短く説明する想起練習です。指定がなければ10問、指定があれば1〜30問の範囲でその問題数を使います。Aは `floor(問題数 × 40%)`、Bは残りとし、10問ならA4/B6です。両TrackともLevel 1の短い「○○とは何ですか？」形式を維持します。

各1問の `Primary Terms` は1語句に限定します。これにより、1つの回答とScoreで複数語句のRecall Scoreが更新されることを防ぎます。taxonomy上の複合名称は1語句として扱います。

選択は通常問題と同じ総合理解度、Attempts、Last Studied、Last Score、Next Review、忘却度、関連語句、最近の出題を使います。通常説明の弱点度・出題難易度・発展判定には `Explanation Score`、暗記語句の弱点度・定着判定には `Recall Score` を使い、自己モードが未評価なら新規候補として扱います。さらに、通常説明の低得点を暗記候補へ、暗記語句の低得点を通常説明候補へ加点します。`Score` は両形式を統合し、モード別Scoreは「暗記はできるが応用が弱い」などの差を残します。

問題選択の補助結果は次のコマンドでも確認できます。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD
```

暗記語句モードは次のように確認できます。

```bash
python3 skills/security-specialist-trainer/scripts/study_helper.py plan \
  --root . --date YYYY-MM-DD --mode term-recall --count 10
```

## 採点と理解度更新

採点はキーワード数ではなく、問題に必要な次の観点を選び、該当観点の配点を100点へ正規化します。

1. 定義
2. 原理
3. 成立条件
4. 攻撃・利用シナリオ
5. 対策とその理由
6. 類似概念との差・限界

問題別に点数、良かった点、足りない点、短い模範説明をセッションへ追記します。内容に応じて、復習用のMermaid図も追加します。その後、`record` コマンドが `terms.md`、`domains.md`、`history.md` を冪等に更新し、最後にSessionを `graded` にします。`record` は更新前に、現行Sessionの `Mode` が `diagnosis`、`adaptive`、`term-recall` のいずれかと1行だけ存在すること、`Mode: diagnosis` / `adaptive` が `sessions/理解・応用問題/`、`Mode: term-recall` が `sessions/暗記語句問題/` にあること、必須の `Question Count` が1〜30の整数で実際の問題数と一致し、Q番号が `Q1` から重複・欠番なしの連番であることを検証します。Modeなしや配置制約の後方互換は旧保存先のSessionにだけ適用します。`QX`、`Q 2`、`Q01` など形式外のQ見出しも拒否します。不一致は自動補正せず、progressを更新する前に停止します。途中停止時はStatusが `grading` に残り、再実行してもAttemptsや履歴行を重複させません。低難易度での満点だけで応用力100とは見なさず、Level 1〜4の証拠スコアには上限を設けます。詳しい式は [references/scoring-rules.md](references/scoring-rules.md) にあります。

暗記語句問題は、定義50%、目的・役割30%、重要な特徴・仕組み20%を基準に意味で採点します。短い正答を評価し、求めていないシナリオ適用や高度な対策がないことでは減点しません。Recall ScoreとSession平均には0〜100の生点を保持し、総合理解度と分野スコアの直近証拠へ反映するときだけLevel 1の証拠上限を適用します。

## 復習タイミング

基本間隔は現在理解度に応じて1日、2日、5日、12日、30日です。直近の点数、出題難易度、連続した理解の安定性で補正します。直前と今回がともにLevel 5以上の高得点の場合だけ長期安定として延長し、Level 1暗記問題の100点はこの連続成功へ数えません。Next Reviewは両モード共通のままです。期限前は出しすぎず、期限が近い・過ぎた概念は忘却度を上げます。100点の概念も除外せず、Level 5相当で安定していれば数週間後に再びシナリオ問題として扱います。

## 実際の利用例

1. チャットで「問題作って」と依頼する。
2. Codexが理解・応用問題を `sessions/理解・応用問題/YYYY-MM-DD.md`、暗記語句問題を `sessions/暗記語句問題/YYYY-MM-DD.md` に作る。
3. 各 `### 回答` の下へMarkdownで回答を書く。
4. チャットで「採点して」と依頼する。
5. 採点結果と3つのprogressファイルが更新され、必要に応じて `復習用/` に図解ノートが追加される。
6. 翌日以降、再び「問題作って」と依頼する。

分量や傾向は自然文で変更できます。例: 「今日は3問」「Web系を多めに」「新しい概念多め」「科目Bのログ分析っぽく」「暗記語句問題を20問」。

## 検証

補助ロジックとSkill構造の回帰テストは標準ライブラリだけで実行できます。

テストファイル名の必須接頭辞 `test_` より後ろ、テストクラス名、`test_` で始まるテストメソッド名は、ローカルおよびCIのログから確認内容が分かるよう日本語で記述します。新しいテストでもこの命名規則を維持します。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s skills/security-specialist-trainer/tests -v
```

GitHub Actionsでも、ブランチ名にかかわらずすべての `push` で同じテストをPython 3.14上で実行します。
